# Windows 发布验收清单

每个候选版本都在干净的发布提交上执行。记录版本、提交 SHA、安装包 SHA-256、Windows 版本、测试日期和测试人。自动化结果不能替代下列真实桌面流程；涉及 EVE SSO/ESI 的步骤使用维护者自己的测试角色。

## 构建前

- [ ] `git status --short` 无输出，`release-config.local.json` 只含四个公开字段，不含 Client Secret。
- [ ] `vendor\MicrosoftEdgeWebview2Setup.exe` 来自微软官方渠道且 Authenticode 签名有效。
- [ ] 运行 `.\scripts\build_windows.ps1`，全量 pytest、Ruff、Git 差异检查、PyInstaller、冻结烟雾检查和 Inno 编译全部通过。
- [ ] 记录生成安装包的绝对路径和 SHA-256；检查冻结目录与安装包不含 `.env`、数据库、密钥、日志、真实 LocalAppData 路径或私有构建材料。

## 第一台测试电脑

- [ ] 在未安装旧版本的普通 Windows 用户下执行全新安装；确认不需要 Python、终端或管理员权限。
- [ ] 确认开始菜单与桌面快捷方式均能启动应用，且没有控制台窗口。
- [ ] 应用运行时再次点击快捷方式，确认重复启动只显示已有实例提示，不出现第二个窗口或第二个本地服务。
- [ ] 点击添加角色，确认系统默认浏览器打开 EVE 官方授权页，完成授权后桌面窗口显示角色。
- [ ] 建立角色组并执行“同步钱包流水”，核对角色、日期、合计、来源和流水明细。
- [ ] 关闭并重新打开应用，确认角色组、钱包历史和授权状态仍然存在。
- [ ] 在已备份的测试数据上制造损坏密钥：先拒绝“重置本机授权”并确认数据库与密钥未改变；再接受重置，确认数据库和损坏密钥均有备份，角色、分组、统计起点和钱包历史保留，角色要求重新授权。
- [ ] 使用相同 AppId 的新候选安装包执行覆盖升级；确认程序版本更新，数据库、密钥、日志和备份仍在，升级后仍可查看历史并同步。
- [ ] 在无桌面数据库的隔离 Windows 用户下选择导入旧版 v2 数据库；确认角色、组、历史和统计起点保留，角色要求重新授权，源数据库未被修改或删除。
- [ ] 在缺少 WebView2 且可安全还原的测试环境运行安装包；确认安装程序调用微软引导程序。断网或安装失败时应中止应用安装并给出错误，不留下不可运行的半成品。
- [ ] 首次卸载选择“否”，确认默认保留个人数据；重新安装后确认数据可继续使用。
- [ ] 再次卸载时选择“同时删除个人数据”，核对两次确认都出现，只有确认的 `%LOCALAPPDATA%\EVE Income Tracker` 被删除，其他目录不受影响。

## 第二台干净电脑

- [ ] 在第二台干净电脑或全新的 Windows 虚拟机中，从 GitHub Release 下载同一安装包并核对 SHA-256。
- [ ] 完成安装、快捷方式启动、角色授权、角色组创建和“同步钱包流水”；确认这台电脑使用独立数据库，第一台电脑的数据不会自动出现。
- [ ] 关闭并重新打开，确认本机数据保留且不需要终端。
- [ ] 执行卸载并选择保留个人数据；确认程序与快捷方式被移除，`%LOCALAPPDATA%\EVE Income Tracker` 仍在。

## 发布

- [ ] 使用已验收的提交和原始安装包手动创建 GitHub Release，不重新打包。
- [ ] 发布说明包含版本、主要变化、安装包文件名、SHA-256、Windows x64/WebView2 要求，以及未签名安装包可能显示“未知发布者”的说明。
- [ ] 下载一次发布页中的安装包并重新核对 SHA-256。
